# 缓存创建 Token 分类与计费

## 适用范围

OpenAI Chat Completions 与 Responses 的总输入字段包含普通输入、缓存读取及缓存创建时，平台将其归一化为互斥分类。普通输入 = 总输入 - 缓存读取 - 缓存创建。Anthropic input_tokens 原本已经是普通输入，沿用独立字段解析，不再次扣减缓存。

## 字段优先级

- Responses：input_tokens_details 优先于 prompt_tokens_details；Chat 顺序相反。
- 读取：details.cached_tokens，然后顶层 cache_read_input_tokens、cache_read_tokens、cached_tokens。
- 创建：每个 details 对象依次取 cache_write_tokens、cache_creation_tokens、cache_creation_input_tokens、cache_write_input_tokens；然后顶层 cache_write_tokens、cache_creation_input_tokens、cache_write_input_tokens、cache_creation_tokens。
- 只选择首个有效非负整数，显式 0 有效；null、负数、布尔、非整数及非数字不能计费，可继续查找后备。别名不累加。
- 创建字段缺失时不由缓存 miss、地址或端口推断写缓存。读取最多等于输入总量，创建最多等于扣除读取后的剩余输入；越界只记录数值告警。

## 流式与透传

OpenAI 透传先合并原始 usage 中明确出现的字段，再重新归一化。允许下修与清零，缺失的字段保留。通过 usage_received 标记区分全零有效快照与缺失/空 usage；后者不进入成功流式计费，包含按次模型。纯缓存请求不会被当成空响应。观察器不改写原响应字节。

## 总量和费用

原始总量 = 普通输入 + 缓存读取 + 缓存创建 + 输出。上下文门槛沿用本系统含输出的原始总量口径。计费总量按各桶分别乘 Token 倍率、逐桶取整后相加。四类费用使用模型各自单价和原有价格倍率；Token 套餐使用原始总量，API key 累计沿用计费总量，金额套餐沿用既有官方/实际成本策略。

例如普通输入 68、创建 188190、输出 6262、读取 0，总量仍为 194520。缓存创建不会再按普通输入单价收费。若创建单价高于普通输入，正确分类后的费用可以高于旧结果，本修复不调整定价。

## 历史与发布

不凭历史普通输入推算缓存创建，不回写历史费用/额度/总量。旧 CPA 推断创建可能与普通输入重叠，历史记录仍按原持久化总量展示。既有 Anthropic 零值/TTL 和旧 cache_read DTO 后备行为不属于本次修复。
