# API 密钥累计费用溢出修复 Impl

## 任务概述

修复 API Key 生命周期累计费用达到 MySQL 字段上限后，本地计费事务整体回滚的问题。修复后，套餐额度耗尽的请求可以继续按混合计费或余额计费正常落账。

本次不改变套餐优先、余额兜底等业务规则，也不自动补扣历史异常请求。

## 核心代码说明

### 字段扩容

`user_api_key.total_cost` 是 API Key 生命周期累计值，不是单次请求费用。生产历史字段 `DECIMAL(10,6)` 仅能累计到 `9999.999999`，因此扩大为 `DECIMAL(20,6)`，保留原有六位小数精度并显著提高整数范围。

### 幂等升级

升级脚本通过 `information_schema.columns` 检查：

- 表和字段存在；
- 字段不是 DECIMAL、精度小于 20，或小数位不是 6。

只有条件满足时才执行 `ALTER TABLE ... MODIFY COLUMN`。重复执行时不会再次修改容量至少为 20 位且 scale 为 6 的字段，也不会主动缩小已有的更高精度字段。脚本将会话锁等待限制为 15 秒，避免长时间阻塞线上数据库。

### 一致性保护

回归测试同时检查：

- SQLAlchemy ORM 精度；
- 三份初始化/数据库快照中 `user_api_key` 表的字段精度；
- 升级脚本包含结构检查和目标 `MODIFY COLUMN`。
