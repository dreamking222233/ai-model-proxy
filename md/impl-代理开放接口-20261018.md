## 任务概述

为代理端增加可供代理自建 Agent/桌面工作台调用的开放 API，并在代理端提供 API Key 管理和 Markdown 接入文档。开放 API 使用独立的 `agk_` 代理密钥确定租户，用户数据操作再叠加该代理终端用户的 JWT。功能覆盖：

- 代理开放 API Key 的创建、列表、权限替换、撤销和到期控制；
- 代理范围内的注册验证码、用户注册、用户登录及美元余额返回；
- 用户模型调用 API Key 的创建，以及按模型系列和分组绑定；
- 支付宝/微信充值订单创建、比例选择、幂等恢复和最多 120 秒的同步支付等待；
- 代理可见的请求详情和充值记录；
- 代理端页面的权限配置、明文 Key 一次性复制和 Markdown 文档复制。

## 核心实现说明

### 身份与租户

开放请求从数据库中的 API Key 读取 `agent_id`，不使用 Host、Origin、Referer 或请求体中的代理标识。注册和登录只接受该代理的终端用户；充值、等待、请求详情、充值记录和模型 Key 创建均校验代理与用户/订单归属。管理 API 只接受代理管理员 JWT，Key 明文只在创建响应中返回，所有明文 Key、登录、注册和等待响应设置 `Cache-Control: no-store`。

### 模型 Key 分组

`group_mode=unified` 时拒绝系列和分组覆盖字段；`group_mode=special` 时要求同时传模型系列和分组 ID，并通过既有 `ModelGroupService` 校验启用状态及系列归属。开放接口复用用户端 `ApiKeyService`，不会把模型调用 `sk-` Key 与代理 `agk_` Key 混用。

### 充值与支付

充值比例代码固定为 `a=1` 至 `g=7`（每 1 CNY 对应 USD），默认 `e=5`；非 `e` 需要代理开启自定义比例，且不能高于当前代理结算比例。金额、到账美元和代理分润分别按 0.01、0.000001、0.01 使用 HALF_UP 舍入，比例和结算值保存到订单及幂等预约快照。

创建订单必须带 `Idempotency-Key`。服务端先保存 reservation 和预留订单号，再保存本地 pending 订单并调用渠道；重试按快照恢复，微信二维码丢失时只有在渠道确认旧订单关闭后才能换号。支付宝和微信均有查单/关单超时，成功查单和回调必须匹配订单号、应用/商户和金额。创建接口先返回支付宝链接或微信 Native 二维码，等待接口使用单调时钟最多等待 120 秒，渠道状态不确定时保持本地订单 pending 并返回 `wait_timeout + close_result=uncertain`。

### 查询与响应

请求详情按 `request_id AND agent_id` 精确读取并使用代理可见 DTO；充值记录只接受白名单分页/筛选参数并强制注入当前代理 ID。等待支付成功后尽量读取美元余额；若剩余响应预算不足，仍返回 `wait_result=paid`，`balance` 为 `null`，文档提示调用方刷新登录接口获取余额。

## 接口清单

统一前缀为 `/api/agent/open/v1`，请求头使用 `X-Agent-API-Key`。需要用户身份的端点同时使用 `Authorization: Bearer <JWT>`。

| 方法 | 路径 | 主要权限 |
| --- | --- | --- |
| POST | `/auth/email-code` | `auth.register` |
| POST | `/auth/register` | `auth.register` |
| POST | `/auth/login` | `auth.login` |
| GET | `/user/api-keys/group-options` | `user.api_key.create` + 用户 JWT |
| POST | `/user/api-keys` | `user.api_key.create` + 用户 JWT |
| POST | `/users/recharge-orders` | `user.recharge` + 用户 JWT + `Idempotency-Key` |
| POST | `/users/recharge-orders/{order_no}/wait` | `user.recharge` + 用户 JWT |
| GET | `/agent/requests/{request_id}` | `agent.request_detail` |
| GET | `/agent/payments` | `agent.recharge_records` |

管理端路由为 `/api/agent/open-api/keys`，用于列表、创建、替换 scope 和撤销。
