# 渠道-原生透传实施记录

## 任务概述

新增按渠道控制的文本模型原生透传。开关开启后，该渠道接收的 Chat Completions、Anthropic Messages、Responses HTTP/SSE/WebSocket 与 count_tokens 请求保留用户原始模型名、提示词、工具、思考参数、未知字段及协议，不执行系统提示词注入、模型替换、参数归一化、风控扫描或协议桥接；平台仍执行鉴权、模型/套餐准入、计费、日志和渠道健康处理。图片和视频专用生成接口不在本次范围。

## 文件变更

- `backend/app/services/channel_passthrough_service.py`：候选分流、原始 HTTP/SSE 转发、usage 观察、混合回退、count_tokens 与原生 Responses WebSocket。
- `backend/app/services/proxy_service.py`：三个旧文本处理器增加内部渠道白名单；旧 WebSocket 支持首消息回放。
- `backend/app/api/proxy/openai_proxy.py`、`anthropic_proxy.py`：文本路由接入渠道透传分发。
- `backend/app/models/channel.py`、`schemas/channel.py`、`services/channel_service.py`：渠道开关读写。
- `frontend/src/views/admin/ChannelManage.vue`：列表状态及新增/编辑开关。
- 三份初始化 SQL 和 `backend/sql/upgrade_channel_passthrough_20260918.sql`：默认关闭的幂等字段升级。
- `backend/requirements.txt`：显式声明原生 WebSocket 客户端依赖。
- `backend/test_channel_passthrough.py`：透传保真、流式 usage、混合回退、count_tokens 与 WebSocket 状态机测试。

## 核心实现

- 透传候选按用户请求的原始统一模型选取并固定该模型价格；普通候选仍按覆盖规则解析。开启透传但协议不匹配的渠道会从旧链路排除，避免被系统改写后调用。
- 请求 body 和应用层 WebSocket 帧不重建；仅剔除逐跳头、本站凭证和来源身份头并注入上游渠道凭证。
- SSE 在响应头提交前预读首个完整业务事件；无 usage 的首事件错误可回退，已有 usage 或正常事件后不再换渠道。客户端断开后读取任务继续收集当前上游 usage。
- usage 观察副本支持 OpenAI、Anthropic 和 Responses JSON/SSE，区分 usage 缺失与真实零值，并合并缓存 token 明细。
- Responses WebSocket 真正连接上游 WS。握手/首帧发送失败可回退，发送成功后会话固定；response.create/append 串行逐轮准入，按 response id 防重复结算，generate=false 原样发送但不建立生成账单。
- 透传候选在选路时保存 ORM 标量快照；准入检查提交事务并释放请求 Session 后，HTTP/SSE/WebSocket 的延迟计费不再访问失效 ORM 对象。
- WebSocket 混合候选严格按排序逐个尝试。透传 A 握手失败、普通 B 首轮未提交失败后，可继续尝试透传 C；任一候选提交后固定会话。

## 测试验证

- 新增透传测试：18 项通过；旧 Responses WebSocket 测试签名已同步，相关定向回归共 78 项通过。
- 后端测试收集 360 项：358 项通过；2 项会直接访问旧远程视频服务的外部集成脚本因测试环境禁网失败，与文本透传无关。
- Python 编译和 `git diff --check`：通过。
- 前端 `npm run build`：通过，仅有既有资源体积警告。
- 本地数据库已执行幂等升级并核验 `passthrough_enabled tinyint NOT NULL DEFAULT 0`。
- 真实渠道端到端验证：本地接入 `claude-opus-5` 透传渠道后，代理请求体与上游收到的字节 SHA-256 一致，查询串、自定义业务头和 Anthropic 版本头保留；上游响应体与客户端收到的字节 SHA-256 一致。请求按系统提示返回指定文本，成功写入渠道 27 的计费日志并扣减本地测试余额。
