# 缓存创建计费修复实施记录

## 任务概述

修复 OpenAI/Responses 的缓存创建被并入普通输入计费的问题；本次仅本地代码与 GitHub 提交，不更新服务器、不重启服务、不改历史账单与价格。

## 文件变更

- backend/app/services/proxy_service.py：共享字段选择及缓存桶解析；移除 CPA 缓存 miss 推断创建量；流式显式零；四桶总量、上下文与异常日志。
- backend/app/services/channel_passthrough_service.py：仅 OpenAI / Responses 原始 usage 字段快照合并，允许下降和零值；保留 HEAD 的 Anthropic 路径。
- backend/test_cache_creation_billing.py：独立回归测试，包含 SQLite 实际入账、事务回滚和重复请求。
- docs/缓存创建计费.md 与本任务 md 方案/评审/记录。

## 核心实现

共享解析把 inclusive input 拆为互斥普通输入 / 缓存读取 / 缓存创建。别名按明确优先级选择而非累加；零值有效，无效 token 跳过，越界缓存有数值告警并被限制在输入总量内。缺少创建明细时不推断创建。Chat reasoning 差额仍基于未拆分输入；Responses 不新增 reasoning 回退。

实际计费沿用原价格与倍率，分别计算四类成本；原始总量及长上下文采用四桶原始 token，计费总量逐桶乘倍率取整后求和，API key 与套餐沿用现有计费/原始口径。失败事务回滚后仍保留完整实际用量，不重复扣款。历史行不补算。

透传只改变账务观察器，不修改客户端收到的响应；合并原始明确字段后重新生成完整摘要，避免 max 拼接旧普通输入与新缓存桶。
