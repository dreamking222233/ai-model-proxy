# 计费-长上下文阈值配置 Impl

## 任务概述

将模型的长上下文双倍计费阈值从全局固定 `262144` 改为模型级配置。管理端可继续设置是否开启双倍计费，并在开启时设置具体 Token 阈值（如 `200000`）。现有模型升级后默认仍为 `262144`，精确保留原计费边界。

本次只调整长上下文倍率的阈值来源；2 倍倍率、上下文 Token 计算口径、成本公式、套餐额度消费、套餐不足后的余额补扣、纯余额扣减及记账事务均保持原实现。

## 核心代码说明

### 阈值与倍率

```text
threshold = unified_model.long_context_token_threshold || 262144

if long_context_billing_enabled != 1:
    context_multiplier = 1
else:
    context_multiplier = context_tokens > threshold ? 2 : 1
```

边界保持“严格大于”：配置 `200000` 时，`200000` Token 为 1 倍，`200001` Token 起为 2 倍。

### 上下文 Token 口径

未修改原有口径：

```text
context_tokens = raw_input_tokens + raw_output_tokens + raw_cache_read_input_tokens
```

### 请求前预检与真实扣费

- 普通 Token 计费预检按模型阈值判断 1 倍/2 倍，并分别计算 `estimated_total_cost` 与 `estimated_quota_cost`。
- 按请求计费且请求前无法确定输出量时，仍保留原有保守 2 倍预检，只把保守边界从固定 `262145` 改为 `模型阈值 + 1`。
- 请求成功后以真实上游 usage 和同一模型阈值计算倍率。
- `context_token_threshold_snapshot` 记录模型当时配置，历史账单不依赖后续模型配置变化。

### 扣费安全边界

以下代码未修改：

- `apply_balance_charge` 余额扣减；
- 套餐周期额度查询与行锁；
- `consume_quota_amount_after_request` 套餐额度消费；
- `_calculate_balance_charge_after_quota` 套餐不足后的余额补扣；
- `ConsumptionRecord`、`RequestLog` 和 API Key 累计费用写入；
- 本地记账失败处理与事务提交/回滚。

因此本次变更只会让既有成本公式在模型配置的阈值处选择原有的 1 倍或 2 倍，不改变资产扣减控制流。
