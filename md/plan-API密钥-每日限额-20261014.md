# API 密钥每日限额实施方案 v2

## 用户原始需求

深度阅读项目与文档，在 `/user/api-keys` 为每个 API Key 设置每日最大美元额度；余额和套餐等计费来源综合累计，到达上限后停止新调用，返回“当日请求已超出设置最大额度”。提供当日限额重置按钮，每日按北京时间 00:00–24:00 计算。

## 阅读结论与技术方案

- 项目为 FastAPI / SQLAlchemy / MySQL + Vue 2 / Ant Design Vue，现有 Key 支持分组、累计美元消费、累计统计重置。页面已有用户未提交改动，按现状增量编辑。
- `ProxyService._deduct_balance_and_log_once` 是文本、透传、套餐、余额、赠送额度以及美元按次媒体计费共同结算入口。现有 `total_cost` 在套餐/赠送扣减前计算，表示请求美元消费价值，而非余额实际扣款；每日计数复用这一口径。
- 图片积分和积分视频由独立账本计费，未定义美元汇率；不将积分当美元相加。它们仍在该 Key 达到美元限额后被鉴权拦截。
- `user_api_key` 增加 `daily_limit_usd`（NULL=不限额）、`daily_used_usd`、`daily_usage_date`（北京时间日期）。始终累计每日用量，后续启用限额时无需重新计算。新安装与存量升级 SQL 同步提供，计数从升级上线开始。
- 以显式 UTC 时钟转换 UTC+8，读取时过期日期视为零，结算时在现有 Key 行锁内滚动日期并累加。不需要定时任务，不依赖服务器本地时区。
- 累加与原账务同一事务，行锁串行化重置/设置/计费，避免丢失更新。用 Decimal 六位精度。
- HTTP 鉴权后仅对新生成 POST 请求检查上限（达到 `>=` 即拒绝，HTTP 429，code=`API_KEY_DAILY_LIMIT_EXCEEDED`）。模型列表、count_tokens、既有视频查询和下载只鉴权，不检查每日限额，以免阻断在途任务补结算。WebSocket 握手只做身份认证，普通和原生透传每个生成轮次（含首轮、append、二进制 JSON）用独立会话读取最新 Key。
- 请求结束才知道实际用量，已发出的请求正常计费，后续请求停止；不引入预估误拦截、不取消上游在途请求。极限边界存在单次或并发在途超出，页面明确告知。
- 新增创建时可选限额、限额修改接口和独立当日重置接口。修改额度保留今日累计；重置当日累计保留限额。现有累计统计重置不影响每日限额。
- 用户接口均通过 JWT 及 Key 所属用户过滤；Controller 使用全局 ServiceException 处理，无 try/catch。
