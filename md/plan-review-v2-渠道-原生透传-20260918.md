# 渠道-原生透传方案评估（v2）

## 结论

通过。v1 的六项阻塞问题均已补齐，可以进入实施。

## 评估要点

- 透传与普通候选都复用启用、健康状态和熔断过滤，并保持同协议优先及渠道优先级。
- 请求原始字节和重复业务头保留，仅替换本站身份及逐跳头；响应使用 HTTP 客户端解码后的实体时删除 content-encoding/content-length。
- SSE 首事件前可回退，首个正常事件或已有 usage 的终止错误提交后禁止换渠道；1 MiB 未完成事件溢出必须失败并完整收尾。
- 透传计费固定使用原始统一模型，usage 缺失、真实零 usage、按次价格和失败 usage 均有明确口径。
- 原生 WebSocket 在首帧发送后固定渠道，逐轮计费并防重复；generate=false 不收取生成费用。
- 上游渠道实际支持对应原生 HTTP/WebSocket 协议是部署前提，不在系统中做协议伪装。
