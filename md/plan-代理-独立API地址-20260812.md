# 代理独立 API 地址 Plan

- 日期：20260812
- 任务级别：中型任务（后端配置链路、管理端、代理端、用户端及部署文档联动）
- 当前阶段：Review 已通过，待发布

## 用户原始需求

1. 当前 `/agent/system` 展示统一 API 地址，代理不可修改。
2. `/user/quickstart` 当前展示固定的平台 API Base。
3. 需要在 `/admin/agents` 为每个代理配置独立 API 地址。
4. 代理名下用户在 `/user/quickstart` 看到所属代理的 API 地址，而不是固定平台地址。
5. 新 API 域名要能真实访问时，需同步完成 DNS、HTTPS 证书和 nginx 反向代理配置。

## 现有实现分析

- `agent` 表已有 `quickstart_api_base_url` 和 `api_domain` 字段，本次不需要新增表结构。
- `AgentService.build_public_site_config()` 已在代理站点配置中返回 `quickstart_api_base_url`。
- `/api/user/profile/site-config` 已将 `quickstart_api_base_url` 映射为前端消费的 `api_base_url`。
- `/user/quickstart` 已请求登录用户的站点配置，但管理端当前没有提供配置入口。
- 现有服务层只对 API Base 执行去尾斜杠，没有校验协议、凭据、查询参数或路径。
- 代理未配置地址时的共享 API 回退使用了空的代码默认值，没有读取数据库 `system_config.api_base_url`，导致生产代理站可能返回空地址。

## 技术方案

### 1. 配置语义

- 管理员在 `/admin/agents` 填写完整 API Base URL，例如 `https://api.agent.example.com`。
- 仅允许 `http` / `https` 协议，禁止用户名密码、查询参数、片段和业务路径。
- 地址统一去除尾斜杠。
- 留空表示跟随平台 `system_config.api_base_url`，不在代理记录中固化当前共享地址。

### 2. API 域名识别

- 保存独立 API Base URL 时，后端自动提取主机名写入 `agent.api_domain`。
- 使用平台共享 API 或清空配置时，`api_domain` 设为 `NULL`。
- 保存时检查 `frontend_domain` / `api_domain` 的跨字段冲突，避免一个域名被两个代理解析。

### 3. 共享地址回退

- 代理列表、代理系统页、公开站点配置和登录用户站点配置统一从数据库读取平台共享 API 地址。
- 管理端同时获取“实际生效地址”和“代理单独配置值”，保证留空回退语义可编辑。
- API Key 鉴权同时识别静态 `PLATFORM_API_HOSTS` 和数据库共享 API 主机名，避免平台地址变更后代理用户直连被拒绝。

### 4. 历史数据迁移

- 发布时执行幂等 SQL，仅清空 `api_domain IS NULL` 且等于当前或已知历史共享 API 的固化值。
- 已配置独立 `api_domain` 的代理不会被迁移脚本修改。

### 5. 三端页面

- `/admin/agents`：新增“独立 API 地址”输入，列表展示实际生效地址。
- `/agent/system`：继续只读，明确由平台管理员配置。
- `/user/quickstart`：优先使用 `quickstart_api_base_url`，兼容 `api_base_url`。

### 6. nginx 与网络边界

- 代理配置保存仅修改业务数据，不由 Web 进程自动修改 nginx。
- 新域名上线前需完成 DNS 解析、HTTPS 证书和 nginx `server_name`，并将 API 请求反向代理至 `127.0.0.1:8085`。
- 若配置的地址本身已经由现有 nginx 接入后端，无需重复新增 server block。
