## 用户原始需求

当前系统包含管理端、用户端和代理端：

- 管理端通过 `/admin/agents` 开通和管理代理。
- 普通用户在线充值比例固定为 `1 人民币 : 5 美元/图片积分`。
- 代理结算比例固定为 `1 人民币 : 7 美元/图片积分`，相关订单与现金分润可在 `/admin/payment-orders`、`/admin/agent-cash` 和 `/agent/payments` 查看。
- 用户通过 `/user/recharge` 充值美元余额、图片积分或购买套餐。

需要新增代理自定义定价能力：

1. 管理员可在 `/admin/agents` 控制代理是否具备自行设置充值比例的权限。
2. 获得权限的代理可在 `/agent/system` 设置当前站点用户的充值比例，例如设置为 `1:1`。
3. 代理对平台的结算比例仍固定为 `1:7`，代理获得用户售价与固定结算成本之间的人民币差价。
4. 美元余额和图片积分使用同一个代理自定义比例。
5. 开启自定义定价权限后，该代理站用户只能在线充值美元余额或图片积分，不能在线购买套餐；`/user/recharge` 直接隐藏套餐付费入口。

## 当前实现分析

### 多租户与站点配置

- ORM：`backend/app/models/agent.py::Agent`
- 请求站点解析：`backend/app/services/agent_service.py::AgentService.get_site_context_from_request()`
- 公开站点配置：`AgentService.build_public_site_config()`
- 管理员代理接口：`backend/app/api/admin/agent.py`
- 代理站点配置接口：`backend/app/api/agent/system.py`

`Agent` 当前已有：

- `online_recharge_enabled`：代理站在线充值总开关。
- `subscription_online_recharge_enabled`：代理站套餐在线购买开关。

当前没有“自定义定价权限”和“站点充值比例”字段。

### 在线充值与代理分润

核心逻辑位于 `backend/app/services/payment_service.py`：

1. `create_recharge_order()` 在创建订单时计算到账资产和代理分润。
2. `_calculate_amounts()` 当前从全局配置读取用户到账比例与代理结算比例。
3. `payment_recharge_order` 保存 `credited_usd`、`credited_image_credits`、`agent_settlement_rate`、`agent_income_cny` 等财务快照。
4. 支付成功后 `_credit_agent_cash_balance()` 按订单中的 `agent_income_cny` 给代理现金余额入账。

当前配置：

```text
普通用户余额到账比例 = 5
普通用户图片积分到账比例 = 5
代理余额结算比例 = 7
代理图片积分结算比例 = 7
```

现有代理站用户也固定按用户比例 `1:5` 到账。以充值 100 元为例：

```text
用户到账 = 100 * 5 = 500
代理成本 = 500 / 7 = 71.43 元
代理差价 = 100 - 71.43 = 28.57 元
```

若代理把站点比例设置为 `1:1`：

```text
用户到账 = 100 * 1 = 100
代理成本 = 100 / 7 = 14.29 元
代理差价 = 100 - 14.29 = 85.71 元
```

支付成功后的资产入账和现金分润均读取订单快照，因此本功能只需保证下单时使用正确的有效比例，历史订单无需重算。

### 套餐在线购买

- `/api/user/payment/subscription-plans` 返回可在线购买套餐。
- `PaymentService.assert_recharge_enabled_for_site()` 在创建套餐订单前检查站点开关。
- `/user/recharge` 根据公开站点配置中的 `subscription_online_recharge_enabled` 显示套餐入口。

当前检查主要基于请求域名解析出的 `AgentSiteContext`。为避免代理用户直接请求共享 API 域名时绕过站点策略，本次套餐限制和充值总开关还必须按登录用户的 `agent_id` 查询真实代理配置并执行服务端校验。

## 技术方案设计

### 1. 数据模型

在 `agent` 表新增：

| 字段 | 类型 | 默认值 | 含义 |
|---|---|---:|---|
| `custom_recharge_rate_enabled` | `SMALLINT` | `0` | 管理员授予的代理自定义定价权限 |
| `custom_recharge_rate` | `DECIMAL(12,6)` | `5` | 代理站统一的美元余额/图片积分到账比例 |

在 `payment_recharge_order` 表新增：

| 字段 | 类型 | 默认值 | 含义 |
|---|---|---:|---|
| `user_recharge_rate` | `DECIMAL(12,6)` | `0` | 下单时实际使用的用户到账比例快照 |

兼容原则：

- 历史代理默认权限关闭，行为继续使用全局普通用户比例 `1:5`。
- 关闭权限时保留已设置的比例，重新开通后可继续使用。
- 历史支付订单的用户比例快照保持 `0`，已有到账量和结算快照仍作为历史财务依据。
- 新增幂等升级 SQL，并同步两份初始化结构文件。

### 2. 权限与接口边界

管理员接口：

- `AgentCreate` / `AgentUpdate` 仅允许管理 `custom_recharge_rate_enabled`。
- `/admin/agents` 列表返回权限状态和当前配置比例。
- 管理员从关闭切换为开启权限时，必须校验代理已保存比例仍处于当前动态上限内。

代理接口：

- 新增专用 `AgentSiteConfigUpdate` Schema，替代代理端复用管理员 `AgentUpdate` 的方式。
- 代理端只允许修改站点公开信息、套餐原始开关和 `custom_recharge_rate`。
- 修改 `custom_recharge_rate` 时，服务层验证管理员已授予权限。
- 代理不能修改 `custom_recharge_rate_enabled`。
- 管理员权限变更与代理比例变更均复用 `operation_log`，记录操作人、代理 ID、来源及前后值。

### 3. 比例校验

统一比例精度为 6 位小数，允许范围：

```text
0.01 <= custom_recharge_rate <= min(余额代理结算比例, 图片积分代理结算比例)
```

上限按当前配置为 `7`。这样可以允许代理零差价销售，但不会生成负分润订单。

校验同时在 Pydantic 基础类型和 Service 动态配置边界执行，并在保存比例、管理员开启权限、用户下单三个时点校验。所有业务异常继续使用 `ServiceException`。

若运行时代理结算比例被调低，发布前 SQL 必须检查已开启权限代理是否超限；发现超限时升级脚本通过 `SIGNAL` 终止，需先修正比例或关闭其权限，再发布配置。

### 4. 有效充值比例

在 `AgentService` 定义不可变值对象 `AgentRechargePolicy`，并以
`resolve_user_recharge_policy(db, user)` 作为登录用户支付决策的唯一权威入口。策略包含代理状态、在线充值总开关、套餐原始/有效开关、权限状态、两类有效用户比例、两类代理结算比例和动态上限。

由后端集中解析有效比例：

```text
直营网用户：使用全局普通用户比例（当前 1:5）
代理用户 + 未开通权限：使用全局普通用户比例（当前 1:5）
代理用户 + 已开通权限：余额与图片积分都使用 agent.custom_recharge_rate
```

`PaymentService.create_recharge_order()` 消费该策略，再将对应充值类型的有效用户比例传入 `_calculate_amounts()`。代理结算比例仍从全局固定配置读取，订单快照 `user_recharge_rate`、`agent_settlement_rate` 和最终到账/分润金额。

当 `user.agent_id` 非空但代理不存在、已停用或配置非法时，策略解析失败关闭并抛出明确的 `ServiceException`，不得回退为平台直营网策略。请求域名上下文仅参与公开展示、账号归属校验、来源快照和支付回跳，不参与登录用户的比例或购买权限决策。

### 5. 套餐限制

有效套餐在线购买开关定义为：

```text
在线充值总开关开启
AND 套餐原始开关开启
AND 自定义定价权限关闭
```

限制同时作用于：

1. 公开站点配置：返回有效的 `subscription_online_recharge_enabled=false`。
2. 套餐列表接口：返回空列表。
3. 创建套餐订单接口：抛出明确业务异常。
4. 用户充值页：不渲染套餐付费模式和套餐内容。

已有套餐、代理人工发放套餐、代理套餐库存和历史套餐订单不受影响。

配置切换采用订单创建时快照语义：已创建的待支付按量订单继续按原比例快照入账直至订单过期；开启自定义定价前已经创建的待支付套餐订单仍可按原订单完成支付。配置变更只限制变更后创建的新订单，不批量关闭、重写或取消已有订单。

### 6. 前端改造

#### 管理端 `/admin/agents`

- 列表增加“自定义定价”权限状态和当前站点比例。
- 新增/编辑弹窗增加权限开关。

#### 代理端 `/agent/system`

- 有权限时展示统一充值比例数值输入。
- 展示可设置上限，保存时提交 `custom_recharge_rate`。
- 自定义定价开启时，套餐在线充值控制呈禁用状态，不提交有效值覆盖原始配置。
- 无权限时不展示比例编辑控件。

#### 用户端 `/user/recharge`

- 从站点配置读取余额和图片积分有效比例，移除所有硬编码 `5`。
- 到账预估、比例文案、快捷金额卡片和自定义金额结果使用同一有效比例来源。
- 有效套餐开关关闭时完全不显示套餐付费模式。

## API 返回字段

公开接口和登录用户 `/api/user/profile/site-config` 只返回有效配置：

| 字段 | 含义 |
|---|---|
| `balance_recharge_rate` | 美元余额有效比例 |
| `image_credit_recharge_rate` | 图片积分有效比例 |
| `online_recharge_enabled` | 有效在线充值总开关 |
| `subscription_online_recharge_enabled` | 叠加自定义定价规则后的有效套餐开关 |

代理鉴权接口 `/api/agent/system/site-config` 额外返回：

| 字段 | 含义 |
|---|---|
| `custom_recharge_rate_enabled` | 管理员授予的自定义定价权限 |
| `custom_recharge_rate` | 代理保存的统一比例 |
| `max_custom_recharge_rate` | 当前可设置的动态上限 |
| `subscription_online_recharge_configured` | 套餐在线购买原始配置 |

管理端代理 DTO 返回权限、保存比例及有效状态。接口不新增语义模糊的 `recharge_rate` 字段；余额与图片积分始终使用各自明确的有效比例字段。

## 验收标准

1. 历史代理升级后默认没有自定义定价权限，用户到账和套餐展示行为不变。
2. 管理员可在 `/admin/agents` 开启或关闭代理自定义定价权限。
3. 未获权限的代理调用接口修改比例会得到业务错误。
4. 获得权限的代理可在 `/agent/system` 将比例设置为 `1`。
5. 自定义比例为 `1` 时，用户充值 100 元美元余额到账 `$100`，代理现金分润为 `85.71` 元。
6. 自定义比例为 `1` 时，用户充值 100 元图片积分到账 `100` 积分，代理现金分润同为 `85.71` 元。
7. 两类按量充值的代理结算比例快照仍为 `7`。
8. 两类按量充值的用户比例快照为下单时有效比例；之后修改比例不影响该待支付订单。
9. 自定义定价权限开启后，用户充值页无套餐付费入口，套餐列表为空，直接创建新套餐订单被服务端拒绝。
10. 权限切换前已创建的待支付套餐订单仍可按订单快照完成，直至订单过期。
11. 关闭权限后，用户到账恢复全局 `1:5`；套餐是否显示恢复由原套餐开关决定。
12. 普通直营网用户继续按各自全局比例充值并可按平台配置购买套餐。
13. 登录代理用户通过共享 API 域名请求时，展示和下单仍按其 `user.agent_id` 对应策略。
14. 代理不存在、停用、比例非法或超出动态上限时失败关闭，不回退到直营网策略。
15. 比例 `0.01` 和动态上限可保存并下单；0、负数、超上限和超过 6 位小数被拒绝。
16. 推广奖励继续按实际到账资产计算并由平台承担，不减少代理订单现金分润。
17. 权限和比例变更在 `operation_log` 中可追溯。
18. 已支付和历史订单、已有套餐、代理人工发放套餐不被修改。

## 风险与控制

### 财务边界

- 风险：自定义比例高于代理结算比例会产生负分润。
- 控制：保存时和下单时双重校验动态上限；订单仍保存最终到账和分润快照。

### 站点上下文绕过

- 风险：代理用户直接调用共享 API 域名可能得到平台站点上下文。
- 控制：支付权限和有效比例以登录用户的 `agent_id` 对应代理配置为准，域名上下文只用于站点展示和回跳地址。

### 配置切换一致性

- 风险：开启权限后套餐前端隐藏，但共享 API 或旧接口仍可创建新订单。
- 控制：公开配置、登录用户配置、列表接口、创建订单统一消费用户归属策略；已有待支付订单按创建时快照继续有效。

### 推广奖励成本

- 风险：自定义比例会同步改变按到账资产计算的推广奖励量。
- 控制：推广奖励明确由平台承担，保持现有奖励算法和代理直接分润公式，并加入带推广关系的两类充值回归测试。

### 配置审计

- 风险：财务权限或比例变更无法追溯。
- 控制：复用操作日志记录管理端权限和代理端比例的操作人、来源及前后值；配置与对应日志在同一事务提交，日志失败时配置回滚。

### 历史数据

- 风险：代理修改比例后旧订单展示与新订单不同。
- 控制：不重算历史财务数据，以订单创建时到账与分润快照为准。

### 数据库发布

- 风险：代码先于字段发布会导致 ORM 查询失败。
- 控制：上线顺序固定为备份、执行幂等升级 SQL、校验字段、发布后端、构建前端、健康检查。

## 回滚方案

1. 管理端关闭全部代理的自定义定价权限，业务立即恢复全局 `1:5`。
2. 回滚前后端代码时保留新增数据库字段，避免破坏已创建订单和简化再次发布。
3. 不回改历史充值订单、代理现金余额和现金流水。
4. 如需数据库结构回退，先确认旧代码已发布，再单独执行字段删除；默认不建议删除兼容字段。

## 非目标

- 不修改代理固定 `1:7` 结算配置。
- 不修改套餐模板售价、代理拿货价或套餐返现规则。
- 不限制代理人工发放套餐、套餐库存或已生效用户套餐。
- 不重算任何历史订单与现金流水。
- 本阶段不执行生产部署。
