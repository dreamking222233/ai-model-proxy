# 会话标识透传实施方案

## 用户原始需求

Claude Code 经 ai-model-proxy → CPA → sub2api 调用 GPT 时，缓存命中率间歇下降。用户要求优化 ai-model-proxy，提交 GitHub、更新服务器并再次测试。本地原项目位于 `/Volumes/project/modelInvocationSystem`，服务器为当前已授权的 Ubuntu 主机。

## 本次范围与技术方案

修复已确认的请求头丢失：`ProxyService._extract_forward_headers()` 在 Anthropic 分支透传 `X-Claude-Code-Session-Id`、`X-Claude-Code-Agent-Id`。使用现有大小写无关索引，去掉标识两端空白，过滤空值及非字符串值；缺失时不生成新 ID，继续允许 CPA 从正文 metadata 取 session。

这两个客户端头适用于 Anthropic 通道，沿用现有受控白名单。认证头仍由渠道配置生成；不放行任意请求头。转发方法供流式及非流式请求共用。

本次不重写 system、工具定义或历史内容：MCP 新增说明的入口来源未取得证据。亦不将 Session-Id/session_id 的供应商路由疑点视为已证明原因。本补丁修正兼容性缺陷，不保证所有请求缓存超过 95%。

## 部署与回滚

服务器 `/root/ai-model-proxy` 当前 main 无未提交修改。部署前核验应用文件及 Git 起点，备份本次修改文件与部署状态。不写入或输出 .env、真实用户凭据。

服务器更新使用 fast-forward，避免覆盖现场修改。后端 systemd 使用 SIGTERM，停止超时 90 秒；在现有请求完成后安排重启。若启动或健康检查失败，恢复修改前文件及原 Git 版本并重新启动。恢复操作仅针对本次改动，不使用清理未跟踪文件或强制覆盖无关内容的命令。
