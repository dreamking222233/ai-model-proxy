# 流式透传错误记录修复方案

## 用户原始需求

修复用户 `18669212049` 请求中大量显示“上游成功响应未包含可计费用量”的问题，完成后暂不更新服务器；如确有数据库变更则只更新本地数据库，并将最新代码及必要 SQL 提交 GitHub。

## 调查结论

- 错误集中在 Anthropic 原生透传的流式请求。
- 上游实际返回过 502 和账户并发限流 429，部分错误在 HTTP 200 建立后通过 SSE `error` 事件返回。
- 当前观察器只设置 `failed=True`，未保留错误事件内容；结算时因此落入“缺少用量”的默认文案。
- `_prefetch_stream()` 会把 `ping` 心跳当作可用首事件，导致错误流无法在响应提交前回退。

## 技术方案

1. 在 `UsageObserver` 增加上游流内错误详情字段，解析 Anthropic、OpenAI 和 Responses 格式的 `error` 事件。
2. `_finalize()` 优先记录底层异常或观察器捕获的 SSE 错误，最后才使用缺少用量兜底文案。
3. `_prefetch_stream()` 忽略注释和 `ping` 心跳，继续读取真实数据、终止事件或错误事件；错误事件无用量时回退到后续候选。
4. 增加回归测试，验证错误原因保留、心跳不会提前判定成功、正常流不受影响。
