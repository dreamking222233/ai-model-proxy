# 渠道-原生透传实施方案 v2

## 用户原始需求

按渠道配置透传，不按模型。原生满血渠道开启后，其所有模型请求 1:1 转发，包括用户提示词、工具调用、思考强度、Messages 协议等，仅保留正常鉴权与计费。相同模型 A 渠道开启、B 渠道关闭时，分别使用透传与现有处理逻辑。尽量减少对现有系统的改动。

## 范围与技术方案

用户已确认：本次仅覆盖所有文本模型的 OpenAI Chat、Anthropic Messages、Responses HTTP/SSE/WebSocket 和 Messages count_tokens；不包含图片/视频专用生成接口。

- 新增 channel.passthrough_enabled，默认 0。管理端渠道新增/编辑开关及列表状态，影响该渠道全部文本模型。
- 保留原始 HTTP body 字节、查询串和客户端协议端点；透传请求不做模型重写（actual_model_name、responses: 指令不适用）、提示词注入、风控扫描/标记、上下文限制、缓存标记改写、参数删改或协议桥接。未知字段也原样保留。
- 仍校验 API Key、用户/站点归属、模型可用性、套餐余额与低资产并发；复用现有计费倍率、缓存用量解析、成功/失败日志与健康状态处理。只解析请求/响应副本用于路由、预检及计费。
- HTTP 原始请求头保留协议/客户端扩展头；剔除逐跳头、Host、客户端本站认证/站点路由头，换成渠道认证。保留 Content-Type（包括 multipart boundary），响应字节与状态码原样透传，剔除逐跳头；使用 httpx 的解码字节时同步去掉 content-encoding/content-length。不把本站 API Key 发到上游。
- 新增独立透传服务与薄分发入口，现有三个文本处理器只增加内部候选渠道参数，用于混合渠道按原顺序回退。关闭开关且无透传候选时直接调用旧链路。
- 透传候选来自用户请求的原始统一模型映射，忽略模型覆盖规则；普通候选仍来自覆盖规则解析后的统一模型，避免透传被全局别名规则改成其他模型。候选按现有协议优先级/渠道优先级合并排序去重。
- 混合渠道每次使用原始请求的独立副本。只有开始向客户端发送响应前，才允许故障切换；不能因计费失败再次调用上游，也不能在已输出内容后重试。
- SSE 按字节转发，另用增量解析器读取 usage（含跨 chunk、多行事件、Anthropic message_start/message_delta 和 Responses 完成事件）。不重构 JSON、事件，不添加身份/安全清洗，不添加 include_usage 等参数。无 usage 不估算 Token 收费；按次模型成功仍按次结算。断连后沿用上游读完结算语义，避免缓存完整响应造成无界内存。
- WebSocket 透传使用真正的上游 WebSocket，原样发送客户端帧和上游帧，保留上一响应 ID/预热/取消等原生语义；逐轮准入、提取终止事件 usage 并记账。已建立会话后固定渠道，不能在有状态会话中切换上游。
- count_tokens 开启透传时调用同协议上游接口，保持旧接口不扣生成费用；关闭时保留现有本地估算。
- 上游必须原生支持用户请求的模型名称及协议；透传不会自动修复不兼容渠道。

## 风险与验证

1. 最高风险为计费丢失/重复和 A/B 请求污染；通过捕获真实发送字节、模拟两种顺序的失败回退及断流验证。
2. 不同上游 SSE 用量口径需复用现有缓存解析，保留未缓存输入、读取缓存、创建缓存分类。
3. 透传开关关闭必须回归现有身份提示、xhigh 降级、模型映射、协议桥接行为。
4. 新增列须先升级数据库再启动新代码；默认关闭，不主动启用任何渠道，不部署生产。
5. 使用本地 mock HTTP/WebSocket 上游验证未知字段、system、tools、thinking、model、SSE、响应头/状态和计费次数；不调用收费生产模型。
6. 运行相关既有计费/协议测试、后端语法检查和前端构建。按项目规范完成独立方案评估，再修订 v2 和方法级 To-Do，评估通过后实施。

## v2：独立评估修订

- 候选绑定原始/覆盖后统一模型与模式。透传全部预检/结算固定用原始模型；旧分支仍自行解析覆盖后模型。原始候选透传 + 覆盖目标普通候选合并，按现有排序，去重。
- 普通处理器增加 allowed_channel_ids 内部参数，限制其只调用指定普通候选；原始 payload 每次深拷贝。混合分发对旧 SSE 在 ASGI 响应头提交前进行有限预读：暂存注释/心跳直到完整第一事件；首事件为错误且无 usage 时完成该迭代收尾并尝试下一候选；首个正常事件即提交，之后不再切换。超出 64 KiB 预读窗口则提交，防止无界缓存。不改无透传候选的旧 SSE 行为。失败候选可写失败尝试日志，只有成功候选计费。
- 透传 HTTP 在返回 Response 前打开上游并检查状态；只有可重试 HTTP 状态或未获得响应头的连接错误才重试。上游成功响应已经获取后发生读取/本地计费异常，不允许重新调用。最终非成功 HTTP 响应保留上游原始状态/实体内容。
- 用量观察器单独维护 usage_seen、终止状态、错误状态和最大 1 MiB 未完成事件缓存。Anthropic 的累计 input/output/cache 字段合并快照而不累加；Responses completed/incomplete/failed/cancelled 等终止事件读取 response.usage。HTTP JSON 也按相同口径观察。无 usage 的 Token 模型记失败不扣费；真实零 usage 可以正常记账；按次仅在协议成功后收费，免费模型成功正常记账。错误中已有真实 usage 的 Token 模型按实际消耗结算；每次尝试 finalized 防重。
- SSE 使用独立上游读取任务 + 有界队列；客户端断连切换丢弃发送模式并唤醒阻塞队列，读取任务继续收集 usage。上游读超时沿用 600s；同一任务 finally 统一计费、关闭 response/client、释放并发租约。等待任务使用取消屏蔽，避免断连取消记账。
- 请求保真定义为原始 HTTP body 字节不改，协议业务路径不桥接，原始查询串不重排；渠道基础 URL 为 origin 时保留 /v1 或无前缀路径，基础 URL 已含 /v1 或端点时去除重复段。HTTP 响应保留解码后实体字节、状态和端到端头（重复头保留）；传输压缩、分块由 HTTP 栈管理，不宣称网络报文逐字节一致。
- 请求头删除 Connection 声明的额外逐跳头，以及所有本站认证、Cookie、X-Site-Host、转发来源身份头，注入渠道凭证；WebSocket 协商头由库生成。保留 Anthropic beta/version 和未知业务头。
- WebSocket 首个消息用于选渠道，透传分支真正拨号上游 WS，首帧发送前的握手失败可以切换候选，成功发送后会话固定渠道。后续 response.create 使用明确或上轮模型做计费准入，确认该模型仍映射到此渠道；原始帧不补模型、不修改 previous_response_id。客户端与上游独立收发；创建轮次 FIFO 等待 response.created 关联 response.id，终止时按 ID 结算、防重复；拒绝不能正确关联的并发状态，不估算账单。generate=false 预热不扣生成费用。断连停止发送新请求，读完现有轮次或超时后收尾。应用消息文本/二进制载荷及顺序保真，控制帧/分片由库管理。
- 普通 WebSocket 仅增加首次消息回放和 allowed_channel_ids；首次尚未输出、可回退失败可交外层尝试下一候选，建立会话后保持旧处理。不会把真实 WS 降级为 HTTP/SSE 来伪称透传。
- 文本模型携带原生 image_generation 工具时透传保留工具，不进入旧图片改写链路；统一模型本身为 image/video 或 image_credit 计费的请求仍归旧媒体链路。本次不扩展媒体工具的专属计费，只结算该文本模型现有 Token/按次价格。
