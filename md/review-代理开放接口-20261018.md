## 通过项

- 租户身份来自已验证的代理 Key；用户 JWT、充值订单和查询结果都按代理归属校验，跨代理记录统一返回 404。
- Key 生命周期包含哈希存储、scope 校验、有效期、撤销和代理停用检查；比例上限、舍入及订单快照也已接入支付结算。
- 新装 SQL 与已有库升级脚本均已提供；开放接口文档覆盖了主要字段、等待状态和网关超时要求，Nginx 样例设置了 130 秒读取超时。

## 问题（按严重程度）

- **P2：等待接口会阻塞异步事件循环。** [`agent_open_api_service.py:731`](/Volumes/project/modelInvocationSystem/backend/app/services/agent_open_api_service.py:731) 在 `async` 等待流程中直接调用同步限流器；限流器会同步访问 Redis，连接/读取超时为 5 秒（[`redis_client.py:21`](/Volumes/project/modelInvocationSystem/backend/app/core/redis_client.py:21)）。Redis 响应慢时会阻塞同一 worker 的其他协程，削弱等待并发能力。
- **P2：关键幂等恢复路径缺少故障注入验证。** 方案要求覆盖预约、落本地订单、渠道下单及凭据持久化之间的崩溃窗口；现有测试覆盖了比例、部分微信恢复和状态分支，但没有看到这些完整窗口的故障注入测试（[`test_agent_open_api.py:423`](/Volumes/project/modelInvocationSystem/backend/tests/test_agent_open_api.py:423)）。实施记录也注明支付沙箱尚未验证；升级 SQL 和并发锁行为同样需要在目标 MySQL 上验证。
- **P3：幂等处理中响应缺少 `Retry-After`。** 有效租约内返回 409，但没有提供可重试时间（[`agent_open_api_service.py:162`](/Volumes/project/modelInvocationSystem/backend/app/services/agent_open_api_service.py:162)）；这不符合方案约定，调用方只能自行猜测重试间隔。
- **P3：前端复制的 Markdown 与正式接口文档不是同一份内容。** [`OpenApiManage.vue:188`](/Volumes/project/modelInvocationSystem/frontend/src/views/agent/OpenApiManage.vue:188) 单独维护了简版文档，遗漏正式文档中的部分生命周期、订单有效期和部署说明；页面却将其称为“完整接口文档”（[`OpenApiManage.vue:96`](/Volumes/project/modelInvocationSystem/frontend/src/views/agent/OpenApiManage.vue:96)），后续容易出现契约漂移。

## 建议

- 将等待接口的限流访问改为异步 Redis，或纳入有界线程池执行。
- 依据方案补齐支付创建各崩溃边界、租约恢复、并发竞争和不确定关单的故障注入测试；上线前在目标 MySQL 执行迁移并完成支付沙箱回归。
- 处理中响应按租约剩余时间返回 `Retry-After`。
- 让复制内容引用或生成自 `docs/agent-open-api.md`，避免维护两套契约。

## 结论

主功能与租户隔离、费率快照及部署超时要求基本覆盖。**建议修复异步阻塞问题，并完成支付恢复与 MySQL 实测后再作为生产就绪实现通过。**实施记录中的定向测试结果本轮无法复跑：当前只读环境没有可用临时目录，`pytest` 在启动阶段退出。
