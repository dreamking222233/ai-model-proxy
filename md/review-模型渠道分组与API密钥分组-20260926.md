# 实施 Review：模型渠道分组与 API Key 分组

## 结论

实现覆盖了 Plan v2 的主要业务链路。初审发现并修复了分组停用回退、count_tokens 越权校验、媒体日志快照遗漏、图片调用契约、视频延迟计费快照和系统倍率重复相乘等问题；本轮复核又补齐了日志 DTO 的分组快照字段及最小失败日志回退，当前代码可进入目标数据库迁移演练。

## 已核对项

- 默认组、专用 Key 系列隔离、组内候选过滤和停用/无渠道错误码已实现。
- Token 计费才加入分组倍率，预检与成功扣费复用冻结上下文。
- 图片、视频和异步视频路由保留旧媒体计费口径，并保存分组审计字段。
- 真实前端文件名与菜单、路由保持一致，API Key 兼容路径无重复定义。
- 新增分组专项测试覆盖默认组切换、专用 Key 越权、组内故障、模型列表过滤和倍率叠加，专项为 6 passed；透传与价格回归为 22 passed（合计 28 passed）。
- 视频创建、恢复和延迟计费均复用创建时分组快照；迁移脚本按列幂等并在历史回填后检查空分组。
- 图片成功/失败日志、视频失败日志和 Responses WebSocket 失败日志均复用请求分组快照；图片、视频媒体金额仍不乘分组倍率。
- count_tokens 本地估算回退现在先解析模型并执行专用 Key 系列/分组校验。
- 统一 Key 在系列存在分组但没有启用默认组时直接报默认组缺失，不再读取未过滤映射；删除分组会清理映射并保留 Key 引用，使旧 Key 得到分组不可用提示。
- 管理端与代理日志 DTO 现在返回 `group_id_snapshot/group_name_snapshot/group_multiplier_snapshot`，失败日志的降级写入路径也保留同一快照。
- 站内模型列表和聊天模型列表现在只统计当前模型系列默认组的启用映射；升级脚本回填按最终启用默认组执行，遗留 `NULL group_id` 会在 `ALTER ... NOT NULL` 阶段显式失败。

- `system_config.price_multiplier` 应保持部署值 `1`；命中用户专属/系列规则时，计费使用该规则而不再与系统倍率重复相乘。
- 全量 pytest：`382 passed`，29 个既有弃用/命名警告；分组、计费、透传和日志专项回归均通过。
- 前端 `npm run build` 通过，仅保留既有资源体积 warning。
- `git diff --check`、Python 编译和前端构建均通过；前端仅保留既有资源体积 warning。
- 两份升级脚本保持一致，未连接实际 MySQL；部署前应先备份并在演练库执行脚本，确认历史映射无 `NULL group_id`。
