# 渠道-原生透传代码审查（第一轮）

## 结论

不通过。发现 1 个 P0、3 个 P1 和 3 个 P2 问题。

## 发现

1. P0：WebSocket 二进制生成帧未进入准入和计费状态机。
2. P1：迟到或重复的 response id 可能把旧轮 usage 记到新轮。
3. P1：合法 SSE 事件在 EOF 前没有空行时会被误判失败并重复调用。
4. P1：WebSocket 混合候选在遇到普通候选后不能继续尝试后续透传候选。
5. P2：httpx 自动业务头和本站 `x-request-id` 破坏头部保真。
6. P2：升级 SQL 的双引号动态语句不兼容 `ANSI_QUOTES`。
7. P2：新增测试被 `.gitignore` 的 `/backend/test_*.py` 规则忽略。

## 修复结果

- 二进制与文本 WS 帧统一解析，response id 先关联再观察 usage，并维护已结算 id 集合。
- SSE EOF 剩余事件结构化分类；首错误后若出现 usage 不再回退。
- 使用显式 `httpx.Request` 避免默认业务头，不再添加本站响应 ID。
- SQL 改为单引号转义，并在 `ANSI_QUOTES` 会话中重复执行验证。
- 新增边界测试提交时使用 `git add -f` 纳管。
